# 计算机体系结构课程设计实验要求

> 依据《体系结构实验指南-2025 秋季》与《课程考核指南》（2026 年秋季）整理。

> 2026-10-19 核对说明：指导书文件名带有“2025”，正文封面为“2026年秋季”。以下区分原文要求与项目自行选择的实现方案；存在歧义时保留原文并向助教确认，不自行修改课程口径。

## 一、实验总体说明

- **实验选题**：超标量处理器设计（铁人三项实验设计）。
- **组织形式**：分组进行，每组 5 人，每组设组长，全班共分为 5 组；评分包括现场验收和实验报告两部分。
- **时间安排**：实验时间从任务布置日起至本学期末结束，考核时间暂定为二月初。
- **板卡安排**：原文说明硬件实验板由院里在实验开始后发放，验收后上缴；具体型号、领取时间待落实。
- **实验目标**：熟悉现代处理器的基本工作原理，掌握流水线、浮点、缓存、多发射、乱序执行、分支预测等设计方法；针对开源指令集、编译器前端与操作系统设计，形成处理器、操作系统以及编译器的完备体系。
- **实验工具**：
  - 语言：HDL/Verilog、C/C++；
  - IDE：Vivado / Synopsys / Cadence EDA；
  - 硬件平台：FPGA 开发板。
- **实验内容**：设计并实现一个 RISC-V 超标量处理器，包含三个实验部分：
  1. **实验 1.1 数据通路设计**：多发射、乱序执行、分支预测；
  2. **实验 1.2 缓存设计**：Cache、MMU、TLB；
  3. **实验 1.3 浮点功能设计**：浮点加法、乘法、除法。

## 二、实验 1.1：数据通路设计

### 2.1 基本要求

| 类别          | 具体要求                             |
| ----------- | -------------------------------- |
| 乱序执行        | 实现乱序执行功能                         |
| 执行单元        | 具有多个执行单元，例如多个/3 个 ALU            |
| ROB         | 实现重排序缓冲区，支持顺序提交                  |
| Issue Queue | 实现发射队列                           |
| 精确中断        | 中断信息在 Commit 阶段处理                |
| 多发射         | 取指宽度 ≥2、Issue 宽度 ≥2、Commit 宽度 ≥2 |
| 指令依赖        | 译码阶段正确处理同周期两条指令间的依赖冲突            |
| 分支预测        | 实现动态 BPU，不允许只使用静态预测              |
| 预测准确率       | 原文为“70%以上”；项目内部采用严格高于 70% 的门槛 |
| BTB         | 实现分支目标缓冲区                        |
| 预测失败恢复      | 能够清除错误路径上的指令并恢复执行                |

乱序执行方案、分支预测算法等不作具体限制，可以自行选择。

“3 个 ALU”为原文举例，并非固定数量要求。Issue 宽度特指从发射队列到执行单元的宽度；仅同时派遣两条指令进入队列不满足该要求。精确中断与同步异常均应有独立验证，不能只用异常或分支 Flush 测试替代中断测试。

### 2.2 进阶要求

- 使用统一发射队列（Unified Issue Queue）。
- 实现返回地址栈（RAS）。
- 使用 Checkpoint 机制恢复流水线。

### 2.3 架构文档要求

- 完整数据通路框图，标明模块、连接关系和各通路发射宽度。
- 模块接口文档，说明输入、输出信号的类型及功能。
- 各模块内部的 RTL 级架构框图及基本工作逻辑。
- 验收时能够介绍处理器架构及数据通路。

## 三、实验 1.2：缓存设计

### 3.1 Cache 基本要求

| 类别   | 具体要求                      |
| ---- | ------------------------- |
| 映射方式 | 多路组相联                     |
| 存储结构 | Tag Array 与 Data Array 分离 |
| 访问方式 | Tag 与 Data 并行访问           |
| 写策略  | Write-back（写回）            |
| 写分配  | Write-allocate（写分配）       |
| 替换策略 | 实现至少一种 Cache 替换算法         |

**进阶要求**：至少实现一种 Cache 优化技术，例如流水线化、非阻塞 Cache、多 Bank、预取、合并写等（也可不在列举范围内）。

### 3.2 MMU / TLB 基本要求

| 类别     | 具体要求                |
| ------ | ------------------- |
| 地址翻译   | 实现虚拟地址到物理地址的转换      |
| 分页机制   | 支持 Sv32 或 Sv39      |
| TLB 结构 | ITLB 与 DTLB 分离      |
| 相联方式   | TLB 全相联             |
| TLB 管理 | 实现表项查找、插入及替换        |
| OS 配合  | 实现对应的 Page Fault 处理 |

原文 OS 部分另写有“用特权指令将页表项（PTE）加载进 TLB”。该表述的预期实现方式需要助教确认。项目暂按标准 Sv32 硬件页表遍历、软件修改内存页表并执行 `SFENCE.VMA` 的路线设计；`SFENCE.VMA` 不是直接写入 TLB 的指令。规范依据及处理方案见[技术调研记录](../research/技术调研-2026-10-19.md)和[项目设计书](../项目设计书.md)。最小监控程序能否替代指定 OS 的演示尚未确认。

### 3.3 评估指标

访问延迟、带宽、吞吐量、Cache 命中率、硬件资源开销。

## 四、实验 1.3：浮点功能设计

### 4.1 基本要求

| 功能   | 具体要求               |
| ---- | ------------------ |
| 浮点加法 | 实现对阶、加法、规格化、舍入     |
| 浮点乘法 | 实现尾数乘法、指数计算、规格化、舍入 |
| 浮点除法 | 实现浮点除法、规格化、舍入      |
| 标准兼容 | 遵循 IEEE 754 浮点运算规则 |
| 功能验证 | 使用给定测试数据验证运算正确性    |

浮点运算还需要考虑 NaN、无穷大等特殊值的处理。

原文未明确指定 FP32/FP64、全部舍入模式的测试范围、是否必须接入 CPU 指令执行路径，以及是否要求完整 RV32F。独立 FP32 部件为项目当前实现方案，不能据此认定课程已经接受该验收形式；给定测试数据亦需领取并纳入回归。

### 4.2 进阶要求

- 对浮点部件进行流水线化、并行计算等优化。
- 对比分析优化前后的性能差异。

### 4.3 评估指标

功能正确性、运算延迟、吞吐量、硬件资源使用量。

## 五、验证与验收要求

| 类别      | 具体要求                          |
| ------- | ----------------------------- |
| 功能验证    | 验证各模块及集成后处理器的功能正确性            |
| 仿真测试    | 提供仿真结果及分析                     |
| FPGA 验证 | 使用 FPGA 开发板进行硬件验证             |
| 性能测试    | 基本功能完成后，通过 Benchmark 测量 IPC   |
| 性能排名    | 基本要求全部完成后，依据 Benchmark IPC 排名 |
| 频率加分    | 根据 FPGA 时钟频率排名，可申请额外加分        |

### 考核与评分

- 《课程考核指南》明确：开卷考试占个人成绩 20%，课程实验设计占 70%，平时作业占 10%；考勤另按原文公式影响总成绩。
- 下列两条是《实验指导书》内部比例原文，70% 与 50% 合计超过 100%，须向助教核实，不能直接用于成绩计算。

- 现场验收由助教根据现场硬件情况核定，按小组进行验收（要求小组所有成员必须在场），验收成绩占个人课设总成绩 70%。
- 实验报告内容包括实验目的、设计方案（原理说明及框图）、关键代码及文件清单、仿真结果及分析、性能分析、硬件调试、成员分工、实验收获等，占个人课程设计实验总成绩 50%（原文如此）；需要在实验报告对应部分标明完成人姓名。
- 流水线设计功能正确的所有小组中，具有最高时钟频率的前 5 个小组可获得 5–10% 的加分；申请加分的小组需单独提交申请，并另提交一份代码和设计说明。
- 实验严禁抄袭。实验报告或代码（自研部分）出现雷同、回答问题反映出相关工作明显非本人完成等抄袭嫌疑的，现场实验或实验报告按零分处理。

## 六、最终交付要求

### 6.1 设计成果

- 完整设计代码及关键文件清单。
- 处理器数据通路及各模块架构文档。
- 模块接口说明。
- 功能仿真及验证结果。
- FPGA 硬件调试结果。
- 性能测试及分析结果。

### 6.2 实验报告

实验报告需包含：

1. 实验目的。
2. 设计方案、原理说明及架构框图。
3. 关键代码与文件清单。
4. 仿真结果及分析。
5. 性能分析。
6. 硬件调试。
7. 成员分工及对应完成内容。
8. 实验收获。

**提交方式**：实验报告（pdf）和设计代码打包后发送至学生助教邮箱。原文文件名为“2025体系结构课程设计+实验小组编号”，与正文课程年份不一致；实际年度、命名及截止日期以最新通知为准。向 Git 仓库提交设计文档不等同于课程最终报送。

### 6.3 原创性要求

允许参考 BOOM、NaxRiscv、玄铁 C910 等已有开源处理器的设计原理，但要求形成自主设计的处理器架构，不得照抄现有代码或实验报告。

两份课程原文未见明确的 AI 使用政策；AI 辅助是项目拟采用的工作方式，不能写成课程已经明确鼓励或批准。引用和许可证记录不能代替课程对自主设计的要求。
