## 2 P1 最小顺序核测试清单（计划）

P1 活动宽度为 1 槽；接口保持双槽能力。

### 2.1 每类指令

| 类别 | 输入 | 预期结果 | 检查方式 |
| --- | --- | --- | --- |
| LUI/AUIPC | 边界立即数 | rd 正确；AUIPC 以 PC 为基 | 退休记录 + Spike 差分 |
| JAL/JALR | 正/负偏移、目标对齐 | rd=PC+4；目标正确；非对齐目标产生异常 | 退休记录 |
| 分支（6 种） | 取/不取边界、相等/有符号/无符号 | next_pc 正确；不写 rd | 退休记录 |
| Load（LB/LH/LW/LBU/LHU） | 对齐、符号/零扩展、页尾 | 数据/符号扩展正确 | 退休记录 + 内存 |
| Store（SB/SH/SW） | 各字节掩码、连续同地址 | 字节使能正确、内存保持 | 退休记录 + 内存 |
| ALU 立即数/寄存器 | 溢出、移位量 ≥32、比较边界 | 结果与 Spike 一致 | 退休记录 |
| FENCE/FENCE.I | 前后访存、代码修改后执行 | 顺序与取指同步 | 定向测试 |
| ECALL/EBREAK | M-mode | cause 11/3、EPC/tval 正确 | Trap 事件 |
| MRET | 从 trap 返回 | 特权/使能恢复、PC 正确 | Trap 事件 + 后续退休 |
| WFI | M-mode | 按 NOP 或等待（P1 固定 NOP） | 定向测试 |
| CSR 指令 | 6 种形式、rd/rs1=0、只读/非法 | 读写抑制、非法指令 | 定向测试 |

### 2.2 Trap 与握手

| 场景 | 输入 | 预期 |
| --- | --- | --- |
| 非法指令 | 未定义编码、越权 CSR | cause 2，tval=指令 |
| 非对齐 load/store | half 的 bit0=1，word 的低 2 位非 0；byte 总是自然对齐 | cause 4/6，tval=地址 |
| 取指/跳转非对齐 | 目标低 2 位非 0 | cause 0 |
| 访问故障 | PMA 拒绝地址 | cause 1/5/7 |
| 双槽异常（P3） | S0 正常、S1 异常 | S0 先提交，S1 下一拍 |
| 空 ROB 中断 | 中断挂起、ROB 空 | EPC=架构下一 PC |
| 背压 | ready 随机拉低 | valid/payload 保持，无重复/丢失 |
| 复位 | 外部事务按协议静默/排空后同步复位 | 控制状态清零；不能凭清 valid 假定外部事务消失 |
| 启动/终止 | 复位向量、签名写入 | 从 `0x8000_0000` 启动；签名/停机正确 |

### 2.3 P1 CSR/计数器/接口附加门禁

| 场景 | 输入 | 预期 |
| --- | --- | --- |
| 六种 CSR 读写 | rd/rs1=0、rs1≠0 但值为零、zimm=0/31 | 读抑制仅 CSRRW/CSRRWI rd=x0；写抑制按 rs1/zimm 编号 |
| 只读 CSR | 读取 + 写尝试 | 读正常；写产生非法指令，CSR 不变 |
| 计数写/自增 | mcycle/minstret 写入同拍退休 | 写优先，该周期不自增；异常指令不计 minstret |
| 低/高半 | RV32 高低半读写、低半进位 | 64 位值一致 |
| Token 回绕 | 缩小代次宽度，旧响应迟到 | 分配冻结、排空后恢复，旧响应拒绝 |
| 接口夹具 | 0/1/2 槽、资源不足、连续背压、Flush、第二槽异常 | S0/S1 各接收一次；Flush 不复活；Trap 与退休互斥 |

规则和夹具按 P0-02 各轮报告与 [最终验收](progress/P0-02-R2-review.md)核对；当前没有 DUT 运行测试。取消在途恰逢 Token 回绕的联合场景由 P1-A 补测，不能记为 P0 已执行。

### 2.4 P1 门禁

- RV32I 全部指令定向测试通过；Spike 差分覆盖正常退休流。
- M-mode 同步异常（0/1/2/3/4/5/6/7/11）通过；MRET 返回。
- 复位、背压、Flush、单槽与双槽接口边界通过。
- 启动与终止协议在 Spike 与（后续）DUT 上一致。
- 无未解释的断言失败或跳过项。

## 6 已定范围与剩余条件

1. P1 为 RV32I/Zicsr/Zifencei 与最小 M-mode Trap/CSR，M 在 P3；P1 软件不隐含 M/A/F 依赖。
2. P1-A 仅 RAM/总线，UART/结果寄存器在 P1-D/F；CSR/同步 Trap 在 P1-E，平台中断输入先留接口，最终定时器/外部中断能力仍必需。
3. Spike 日志缺少的 CSR/Trap 观察在 P1-E/F 用快照/独立参考补充；正常流后处理标明来源，不伪造 next_pc/Token。
4. 板卡未定时 P1-G 保持未完成/受阻，不记为通过；课程 FPU/OS/Benchmark 等按 D11 跟进。
