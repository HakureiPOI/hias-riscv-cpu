## 2 规范与工具调研

| 编号与一手来源 | 已核实的事实 | 对本项目的影响 |
| --- | --- | --- |
| S1 [RISC-V RV32I 2.1](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html) | RV32I 为固定 32 位指令；无 C 时指令按四字节对齐；数据非对齐支持取决于执行环境 | 首版不引入压缩指令；明确非对齐 Trap 行为，不以随机结果处理 |
| S2 [RISC-V Supervisor 1.13](https://docs.riscv.org/reference/isa/v20260120/priv/supervisor.html) | Sv32 支持两级页表与 34 位物理地址；`SFENCE.VMA` 同步并失效翻译缓存，允许保守的全量失效；Svade 允许通过 Page Fault 管理 A/D 位 | 不截断高 PPN；采用硬件 PTW、ASIDLEN=0、全量失效和显式 Svade 策略；软硬件闭环必须测试 |
| S3 [RISC-V Machine 1.13](https://docs.riscv.org/reference/isa/v20260120/priv/machine.html) | 中断有使能、挂起、委托和优先级规则；条件变化后需在有界时间内评估；WFI 可合法实现为 NOP | 不用同步异常测试代替中断；将 CSR 与中断控制提前设计；限定单核演示平台 |
| S4 [RISC-V F 2.2](https://docs.riscv.org/reference/isa/v20260120/unpriv/f-st-ext.html) | F 包括浮点架构状态、舍入及异常规则；支持几个独立算子不等于支持完整 F 扩展 | FP32 运算模块与 RV32F 集成分开验收；预留舍入模式和异常标志接口 |
| S5 [BOOM Rename](https://docs.boom-core.org/en/latest/sections/rename-stage.html) | 官方文档区分 PRF 与 data-in-ROB；多宽重命名需要同拍旁路 | 首版选择 ARF + RAT + data-in-ROB，减少 PRF 与空闲表恢复逻辑；显式验证槽间 RAW/WAW |
| S6 [BOOM ROB](https://docs.boom-core.org/en/latest/sections/reorder-buffer.html) | ROB 跟踪在途指令，按序提交，在提交头处理异常；Store 需受提交控制 | 借鉴职责划分，独立设计提交与恢复；不直接照搬 BOOM 的 PRF/分支掩码组织 |
| S7 [SoftFloat](https://www.jhauser.us/arithmetic/SoftFloat.html) | 3e 提供二进制浮点软件实现，覆盖舍入、特殊值与异常标志 | 作为 FPU 主参考模型，固定版本和配置；主机语言普通 `float` 不作为唯一判据 |
| S8 [TestFloat](https://www.jhauser.us/arithmetic/TestFloat.html) | 可测试 binary32 等格式；作者明确提醒除法困难舍入与特定算法缺陷仍需补充测试 | 使用生成用例，同时单独构造除法舍入中点附近、极端指数和长尾情况 |
| S9 [HardFloat](https://www.jhauser.us/arithmetic/HardFloat.html) | 提供支持特殊值、非规格化数、舍入和异常的 Verilog 运算模块 | 用于结构与结果交叉参考；当前不将第三方 FPU IP 当作自主浮点设计成果 |
| S10 [Verilator 官方参数](https://verilator.org/guide/latest/exe_verilator.html) | 提供 Lint、波形、覆盖率等功能；不同版本的断言默认设置存在差异 | P0 固定经过冒烟测试的版本，检查断言确已启用；不直接套用参考项目旧版本约束 |
| S11 [Spike 官方仓库](https://github.com/riscv-software-src/riscv-isa-sim) | RISC-V ISA 参考模拟器，支持多类 ISA/特权配置 | 拟作主差分参考；首次接入必须验证内存图、特权、Trap、Svade 和中断注入可对齐 |
| S12 [RISC-V ACT 官方仓库](https://github.com/riscv/riscv-arch-test) | 本次页面默认分支为 act4，文档使用 ACT4、UDB、Sail，并说明 ACT 不能替代完整验证 | 不默认新版本仍使用 RISCOF；先选定并锁定可运行组合，ISA 测试与 OoO 专项并存 |
| S13 [Zifencei 2.0](https://docs.riscv.org/reference/isa/v20260120/unpriv/zifencei.html) | 指令取指与此前写入需要显式同步，分离 I/D Cache 的实现必须提供相应一致性机制 | FENCE.I 首版排空数据访问、写回脏数据、失效 ICache 并重取 |
| S14 [Zicsr 2.0](https://docs.riscv.org/reference/isa/v20260120/unpriv/zicsr.html) | CSR 指令有读写及抑制读/写的具体规则 | 逐项测试 rd/rs1/zimm 为零等组合，不把所有 CSR 操作当成无条件读改写 |
| S15 [M 2.0](https://docs.riscv.org/reference/isa/v20260120/unpriv/m-st-ext.html) | 定义整数乘除结果，包括除零和有符号除法溢出等边界 | 迭代实现仍需完整满足所声明 M 指令，不让 C/C++ 宿主异常决定参考结果 |

S1—S4、S13—S15 采用文档集合 `v20260120` 作为本项目规范基线，而非跟随会变化的 latest 链接。S2 对 A/D、权限、地址宽度等仅作摘要，RTL 实现前仍须逐项形成算法测试表，不能把本记录当作完整规范。

## 4 形成的项目决策

1. 先完成双发射 OoO 的最小正确实现，采用 data-in-ROB、按序保守访存和提交点全量恢复；保留真实性能代价并测量。
2. CSR/Trap、PTW 与 Cache 一致性规则前置到 W1—W2；BPU、Cache、FPU 可独立推进，但必须有负责人和集成测试。
3. 独立 FPU 按明确的 binary32 算子范围验收，不能把它写成完整 RV32F；接入形式在 W1 向助教确认。
4. FPGA 实机为必做项，先验证 BRAM 程序、复位、串口及中断，再集成完整核；板卡资源确定前不承诺 Fmax。
5. 新版架构测试框架与参考模型采用锁定版本，不把“架构测试全过”写为“处理器已经完全正确”。

这些是基于资料的工程判断，尚无本项目 RTL 的面积、时序、预测准确率或 IPC 实测支撑。后续调整必须引用实际结果。
