## 3 冻结时的管理澄清

以下仅修改当前规格和计划文本，不更改已测试实现、生成产物或历史报告，不声称这些澄清已经过 DUT 运行验证：

- 访存请求与 trace 的 Store 数据统一为**低位对齐的标量**：SB/SH/SW 有效数据位为低 8/16/32 位，高位零；byte mask 单独按地址指示 lane。存储桥按地址将低位字节写入目标 lane；原始总线若需要 lane 对齐，由桥转换。`mem_resp_t.rdata` 为按访问宽度提取、低位对齐且零扩展的原始值；LSU 再按 LB/LH/LBU/LHU 得到架构结果，退休 `mem_rdata` 为扩展后的 32 位值。修正“按 lane 对齐但 SB 使用低八位”的矛盾文字。
- 同步异常的 medeleg 只在异常来自 S/U 时选择进入 S；M-mode 异常仍进入 M。中断则按目标级及当前级比较，不混用同步异常的来源条件。
- 核对 CSR 文本残留：mip.MSIP 不由 CSR 写置位，与 MTIP/MEIP 一样由平台输入/机制维护；P1 未接中断源时绑零，CSR 写忽略。P1 只有 M，mcounteren 暂不实现，按未实现 CSR 策略 Trap；P5 加 U 时实现其权限控制。这些是尚未编写的 P1-E 输入，不增加 P1-A 实现范围。
- P1 的 PMP CSR 不实现，访问按项目非法指令策略；最终零项 PMP 的计划单列，避免与 P1 CSR 表冲突。
- 双槽接口的接收数量是反向组合反馈，在上升沿采样；ready 表示至少能收一槽，实际数量以 accept_count 为准，未接收后缀下一拍重排且不重复发送已接收槽。有效数据只在其 valid 有效时有意义。

CSR/中断依据：[Machine 1.13](https://docs.riscv.org/reference/isa/priv/machine.html) 的权限、中断、MSIP 与 counter-enable 小节。其余数据打包和握手为本项目协议选择。当前文档内容与本节一致后作为实施输入；历史报告继续对应其原 Commit。

## 4 覆盖边界与下一步

本轮夹具分别执行了取消在途、回绕阻塞、重复响应等场景；TB 的回绕循环没有同时施加 Flush，因此不能宣称“已取消项恰逢回绕”的联合场景已有独立运行证据。管理方接受本轮已知缺陷修复与所有权路径审查，将该联合用例列为 P1-A 验收前的补测。它不改变冻结的协议，也不允许把验证夹具直接当作生产模块复用。

P1-A 还需用实际 RAM/总线模块验证字节 lane、在途响应、背压与复位边界。P0 的结构/事件夹具只验证约定，不替代这些模块测试。P1-A 不实现取指执行，不产生伪造退休；P1-B—F 才逐步建立真实程序执行和差分，P1-G 依赖板卡。

FPU 接入形式、指定 OS/Page Fault 演示、板卡/EDA、Benchmark 与给定浮点数据继续等待课程确认；P5 前仍需验证 Spike Svade 的 A/D 行为与地址观察语义。16 KiB 页表是演示预算，不保证满足未确定的 OS。上述事项不阻止独立的 P1-A 实施。
