## 3 唯一阻塞组 H01：fault 负向提前返回，绕过已有错误

行号以交付 `ac82706` 的 `verification/p1c/tb/tb_faults.cpp` 为准。

- 第 114–172 行提交/ARF检查、第 198–221 行 fault 初值/身份/副作用检查、第 244–255 行保持检查都会累计 errors。
- 第 223–236 行 initial_arf 与第 257–270 行 hold_change 却在局部 same_regs 比较检出指定寄存器后直接打印 DETECTED、return 1；它们不检查此前 errors，也不会走第 286–288 行的总失败判定。
- 例如故意让 fault cause 观察值错误，正常元数据检查已 errors++；随后按 initial_arf 注入 x1，局部比较仍输出 INITIAL_ARF_DETECTED、exit 1。runner 只按 exit 1 + 指定消息判断，会将含无关错误的探针算作成功。保持变化探针同理。

这是 R2 V03“指定错误类别与其他错误隔离”的未完成部分，不是新增 RTL 功能要求。当前原始负向日志没有显示无关错误，不声称本轮某个实际运行已被掩盖；问题在成功判据允许掩盖它。

另两个注入分支各自直接调用 same_regs，而正常路径通过 compare_arf；应统一观察→监视→分类→最终判定，避免注入专用分支与正常检查分叉。故障分支也应明确核对 commits 与用例 commit_pcs 数量，防止镜像/Token 仅相对于已观察前缀自洽。

R3 仅处理这一组：目标错误单独计数、全部其他错误累计且不可被提前返回忽略，补目标加无关错误和目标未检出的反例，实际总入口在**原预期检出探针**失败时 FAIL。不能只再次给原正常 fault 步骤非零的证据来替代该边界。

## 4 路线

保留整数后端、格式门禁、独立镜像、分支/恢复与正常 16 边沿保持，不重写 RTL、不重做已关闭旧反例。完成 H01 与同 Commit 正常回归后再整体验收。Load/Store、CSR/Trap、完整 DiffTest、OoO/ROB/Cache/MMU/FPU、SoC 替换及 FPGA 仍按原后续边界推进。
