## 2 必须关闭的问题

### R01（高）ISA/CSR 规格含错误语义和相互矛盾的基线

定位：`docs/architecture/csr-support.md:11–17,23–47,72–96`；`docs/architecture/isa-support.md:30,45,60,75,86`。

- CSR 表把所有 `rd=x0` 都视为抑制读，并把 `CSRRWI uimm=0` 视为不写。正确规则是仅 CSRRW/CSRRWI 在 rd=x0 时抑制读；CSRRS/CSRRC 及其立即数形式始终读；CSRRWI 始终尝试写，即使立即数为零。CSRRS/CSRRC 的写抑制由 rs1 的寄存器编号是否为 x0 决定，不能由其值是否为零代替。该错误还传播到退休检查器。
- `misa=0x40000000` 没有置 I 位；本项目选择报告 RV32I，P1 应为 `0x40000100`。`mstatus` 复位为零与 MPP 只支持 3 相互矛盾；按 D04 固定。`mhpmevent3` 应为 `0x323`，`0x747` 为 mseccfg；MPRV 位于 mstatus 低半部 bit 17，不属于 mstatush。核对 RV32 高半部和可选扩展字段，不能为 Svade 顺带承诺 Svadu/Svpbmt。
- 区分整只只读 CSR 的非法写与可写 CSR 内只读位的写忽略；补最低权限编码 `[9:8]`。M-mode 访问已实现的低权限 CSR 不构成越权。未实现地址的默认行为按 D04，不能同时声明全零忽略和非法访问 Trap。
- EBREAK 的 tval 在表中为指令地址，正文却为零，按 D04 统一；条件分支仅在实际跳转时检查目标对齐，JALR 先清 bit 0 再检查。区分跳转目标错误的 EPC（跳转指令 PC）与 tval（错误目标）。最终中断规则必须区分当前权限低于/等于/高于目标权限和委托条件，不能一律要求目标级全局使能位为 1。
- 计数器按 D03；“为避免差分而固定只读零”不作为本项目实现方案。按指令清单核对 RV32I/FENCE/ECALL/EBREAK 的覆盖口径，避免“37 条”造成遗漏；M 扩展的 P3 计划与阶段总述同步。

依据：[Zicsr 2.0 的读写条件表](https://docs.riscv.org/reference/isa/v20260120/unpriv/zicsr.html)、[CSR 权限与地址表](https://docs.riscv.org/reference/isa/priv/priv-csrs.html)、[Machine 1.13](https://docs.riscv.org/reference/isa/priv/machine.html)。规范中的 reserved 与本项目选择的非法指令策略须分开表述，不能把项目策略描述成所有版本的强制要求。实施方沿用锁定的 v20260120，记录核对章节；动态入口需注明实际版本。

### R02（高）公共接口不能完整表达执行、精确异常与双槽接收

定位：`rtl/include/core_types_pkg.sv:142–145,158–265`；`docs/interfaces.md:15–25,77–80,139–141`。

- `issue_slot_t` 只有粗粒度 `op_class_e`，没有原指令或执行子操作，无法区分 ADD/SUB、不同条件分支、LB/LBU 等。`csr_uimm` 仅 2 位，不能表达五位立即数。补齐到 FU 的操作信息，清理立即数的重复表达并说明有效性。
- Fetch 的异常 cause/tval 和预测索引没有完整进入 Decode/Rename/提交元数据；非法指令信息也在 Rename 丢失。没有另行定义保留这些字段的 ROB 分配通道。需要明确从来源到消费者的字段路径，包含第二槽取指故障、非法编码、预测时保存的索引，以及执行后确定的正确 next_pc。允许用独立元数据通道，不要求所有信息进入每个 FU。
- Fetch/Decode bundle 没有反向接收数量；Dispatch 把 `accept_count` 放在前向载荷中。T04 要求双槽仅接收 S0，而通用规则要求 valid/ready 整包稳定，尚未定义消费者如何反馈只收一槽，以及下拍 S1 如何保留。选定一个完整方案：反向前缀接收数量，或整包握手加明确的内部拆包缓冲；同步类型、方向、边沿和稳定性。不能留两个互不相容的方案给 P1 各模块自行选择。
- `seq` 仅保留在仿真包装层；不要在可综合退休载荷和包装层重复携带。按 D05/D06 补事件互斥、Token 分配/回收及回绕前排空范围。

包能编译、结构位宽正确不证明信息足够。R1 增加小型接口夹具，验证部分资源、背压、第二槽异常、Flush/迟到响应及强制回绕场景，不实现 CPU 模块。

### R03（高）退休契约与转换/检查器可把错误或未观测数据判为有效

定位：`scripts/check_retire_contract.py:85–116,135–179,292–359`；`verification/spec/retire/retire_schema.json:37–64,87–99`；`docs/architecture/retire-contract.md:21–32,85–90,115`。

- Spike 转换器将未打印的 next_pc 填为 0，并按行号制造 ROB Token。来源标记不能使这些字段成为观测结果。参考记录须使用明确不可用/null/valid 状态，DUT 记录则要求其必要字段有效；可证明的推导要单列依据。未知权限不得默认 M，无法解析的提交行不得无提示丢弃。
- `csr_we=false` 强制 csr_addr 为 null，不能表示 CSR 只读；`csr_we=true` 强制 csr_rdata 有值，不能表示 CSRRW x0 的读抑制。增加足以区分 CSR 指令、实际读、实际写的有效性，统一硬件类型、文档、schema、转换器与检查器。
- 4 位 byte mask 必须与地址低位和宽度一致。目前 byte 地址末位为 3 的 mask=8 会被拒绝，错误 mask=1 反而可通过；half 地址偏移 2 的 mask=12 同理。明确四字节字内 lane、数据对齐/扩展和非对齐规则。转换器遗漏 LBU/LHU 的 funct3=4/5，随后把它们静默改为无访存。load 数据不能把日志中并不存在的值称为直接观测；写 x0 的 load 等观测缺口也需表达。
- Token 只检查键而不校验内部类型/范围；Trap 的 schema/seq/PC/EPC/target/source 等必需字段缺少相应类型/范围规则。逐条校验不检查 seq 单调，也不能证明宣称的 bundle 顺序。按明确的流边界校验顺序，包级规则在包夹具检查；补齐范围、有效性和错误类型检查。

修复必须有正反两面的例子：合法 CSR 只读/抑制读、所有字节 lane 与半字位置、LBU/LHU、缺失观测，以及错误 Token/Trap/顺序/来源。保留合成、Spike 派生、未来 DUT 三种来源边界。本轮仍不声称已运行 DiffTest。

### R04（中）页表区域并非单一事实，负向检查可能把漂移当拒绝

定位：`software/smoke/link.ld:60–68`；`scripts/check_platform.py:166–201,248–265`；`scripts/gen_platform.py:154–161`。

配置及归一化产物给页表保留 0x4000 字节，即 `[0x8001a000,0x8001e000)`。链接脚本却以 `PLATFORM_STACK_LIMIT` 作为页表终点 `0x8001eff0`，布局检查日志原样输出这个错误终点并 PASS。报告也因此描述“约 20 KiB”。检查仅验证顺序/边界，没有验证页表大小和配置终点完全相等。

从单一配置生成所有必要起止地址，检查 JSON、C、链接符号和 ELF 的精确一致性；对页表起止和大小施加 4 KiB 对齐，单独标出到栈底之间的对齐空隙。当前生成器只要求保留大小为 16 的倍数，须补页粒度约束。

负向探针调用 `gen_platform --check` 后把任意非零视为拒绝；但该命令还可因生成物漂移返回非零，因此不能证明非法配置被语义校验拒绝。严格核对配置验证错误码与对应错误原因，将生成物漂移测试分开，增加合法输入对照。保留现有七类用例，补页表大小/端点和地址 lane 对应检查。

## 3 管理决策（本轮生效）

下表是项目实现选择，非课程教师口径。R1 将其同步到规格、类型、配置、检查器与 P1 计划；无需逐项再次等待管理确认。

| 编号 | 决定与边界 |
| --- | --- |
| D01 P1 ISA | P1 为 RV32I + 六种 Zicsr + 保守 Zifencei、最小 M-mode Trap/CSR；M 扩展仍在 P3，不前移为 P1 前提。普通整数冒烟可继续用 rv32i，目标能力与软件构建 ISA 要分清；无 libc/运行库隐含 M/A/F 依赖。 |
| D02 SFENCE.VMA | P1 无 S/Sv32，SFENCE.VMA 与 SRET 按非法指令；P5 实现既定语义。WFI 可在权限检查后按 NOP；FENCE/FENCE.I 的排空与重取条件写清。 |
| D03 计数器 | P1 CSR 子任务实现 64 位 mcycle/minstret 及 RV32 高低半访问，复位零，允许写；写与自增冲突按规范，异常指令不计入 minstret。不需要额外 HPM 事件单元。明确是否实现 mcountinhibit 和其复位/写生效规则。mcycle 用受控计数或相对关系自检，不与 Spike 周期数直接相等比较；不能因此全局跳过 CSR 检查。 |
| D04 CSR/Trap | P1 MPP 只支持 M=3，MIE/MPIE 初始零，其他未实现位零，mstatus 复位为 0x1800；P1 MRET 仍返回 M。misa 固定报告 0x40000100，写不改变能力。EBREAK tval=0；EPC 保留指令 PC。没有实现且没有明确只读零定义的 CSR 地址，本项目选择非法指令；明确列出的零项 CSR 按其规则。低权限 CSR 未实现与访问越权分开。 |
| D05 提交事件 | 首版共享契约中正常退休与 Trap 同拍互斥，P1/双提交均一致；S0 正常、S1 异常时先只退休 S0，下一拍处理 Trap。保留正常退休的实际 next_pc 与 Trap target_pc 的区别。 |
| D06 Token/seq | 接受 5 位 ROB 项号 + 8 位代次候选；冻结代次的分配者、递增时机、比较及复用规则。回绕前阻止新分配并排空所有仍可返回旧响应的队列、FU、取指/翻译和外部事务；取消请求也需定义收尾。缩小代次宽度的夹具强制回绕并检查迟到响应。seq 仅仿真包装层持有。 |
| D07 Svade/Spike | 最终 Sv32+Svade 目标保持。接受 ISA 参数仅是能力探测，不能作为 A/D 行为已验证证据。P5 前以 A=0、D=0 的 load/store fault、软件改 PTE、SFENCE.VMA 和重执行验证参考模型；若需额外接口，届时提出具体方案，不阻止独立 P1 工作。 |
| D08 页表预算 | 当前冻结为 16 KiB、四个完整 4 KiB 页，范围按 R04；可供一个根页和三个叶页的演示预算，按映射需求分配。明确空隙；不宣称足以承载尚未确定的 OS。 |
| D09 中断平台 | 保留定时器/外部中断能力要求，但不把完整 PLIC/CLINT 设备兼容性新增为课程必交项。平台寄存器和中断输入需有明确契约；预留区域不等于已实现外设。P1 UART/结果寄存器的偏移、宽度、方向、非法访问与副作用写清，纠正结果寄存器“只写”与 RW 描述冲突。 |
