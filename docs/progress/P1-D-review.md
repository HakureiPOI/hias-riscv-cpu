## 3 阻塞项

行号以 b42794c / 9307a54 对应实现为准。

### F01：仲裁归属没有绑定真实握手和响应身份

`rtl/core/p1_bus_arbiter.sv` 第 81–88 行仅凭 ready 设置 owner，没有与请求 valid 相与。被锁定但未接受的 Fetch 若按既定 redirect 规则撤回，同时 bus_ready=1，会在 bus_req.valid=0 时产生虚假 owner；无实际请求就不会有响应，后续客户端可能永久阻塞。第 55–57 行在 owner 非空时仍透传该客户端请求，未强制禁止另一笔总线接受；可复用模块的单事务边界依赖客户端不提出后继请求及下游恰好不 ready。

第 64–67、96–97 行对任意响应握手清 owner，未保存已接受 req_id/gen。反例：LSU A 已接受，先到错误 ID/旧代次响应，核的 S_LSU_RESP 正确拒绝但仲裁已释放归属；随后 A 的正确响应在无 owner 时被丢弃，或误送到后来获准的 Fetch。核只做本地匹配不能补救仲裁丢失的归属。应由真实握手分配身份，匹配响应才完成原事务，错误响应不能抢走 owner。

### F02：V02 缺少逐笔监视，现有统计已不守恒

`verification/p1c/tb/tb_integer.cpp` 第 81–83 行在监视器初始化前产生一个复位释放后的真实边沿；第 127–132 行只做累计，响应按 valid 计数，缺少已接受请求队列。原始 random0 日志 fetch_req=2653/fetch_resp=2654，random1=2544/2545，random2=2555/2556；这说明监视窗口/统计不能证明恰好一次，**不等于认定 RTL 真正产生了重复响应**。入口只约束 data_req==data_resp 和最小数量，未逐笔关联归属/身份/响应、退休与写事件；额外错路 Load 不改变最终 RAM/ARF，也可能保持请求/响应总数相等。

`tb_arbiter.cpp` 只做几次定向选择；响应背压只在同一拍 eval 后就释放，没有跨边沿保持窗口；稳定性只比较 ID/gen，包装甚至未输出响应完整 payload。没有本轮独立字节数组/逐笔队列的三种子事务检查、无主/重复/错身份响应负向，亦未交付新共享路径的取消/迟到/回绕联合证据。旧 P1-A/P1-B 回归不能替代新仲裁组合验证。新 lsu_gate_i 在集成 runner 中没有显式驱动，报告中的该门控覆盖也不成立。

### F03：数据 fault 夹具漏查首拍副作用、身份与边界

`tb_data_faults.cpp` 第 78 行首次 fault 即退出工作循环；第 99–111 行不检查首次 fault 同拍 commit/Trap/RAM 写，后续检查在再次 edge 后才开始。fetch_gen 没有独立初值/保持核对；Token idx 只检查初值，保持比较遗漏 idx。第 80–82 行未在索引 commit_pcs/writes 前检查范围，异常多提交可能变成 C++ 越界，不能给出受控首差异。

本轮仅 DATA 附近与地址 0 的少数故障，没有 LSU 端 RAM 最后合法 byte/half/word 及紧邻越界边界。定向程序的 0x7ffffffc+4 是越过有符号边界，**没有发生 32 位地址回绕**；需补真实 0xffffffff 进位的 EA/PMA 故障用例。

另 `p1d_diff.py` 第 214 行将整个 RAM 参考区预设零。定向 ELF 只初始化 64B，却比较 256B，192B 不来自镜像或 Store 初始化；管理侧按镜像大小与真实 Store 覆盖独立核对确认。应显式初始化或只比较有已知初值的区域，不能依赖 Verilator 的未初始化内存恰为零。已有三种子确实初始化完整 256B，不重开该成果。

### F04：入口的失败证据和看门狗边界不完整

`scripts/check_p1_d.sh` 第 73 行只要 INJECT 非空就无条件 bad，即使原比较器意外返回正常也会制造 FAIL。当前原比较器确实失败，但此行让该机制无法证明未来仍由真实检查路径触发；删除独立的“有开关就失败”，保留原步骤结果传播。

build_program 的 objdump/nm 已受保护，但 run_program/负向路径又在命令替换里执行未保护 nm；随机生成、变体生成也在主机看门狗之外。对这些命令挂起，入口仍可能无界等待。应复用已保护 nm 输出、统一保护实际执行命令并保留真实退出码，不能只依赖容器外层超时。
