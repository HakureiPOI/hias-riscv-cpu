## 3 合入前必须修复

### F01 正常执行路径缺少主机超时保护

位置：[run_ref_smoke.sh 第 75—108 行](https://github.com/HakureiPOI/hias-riscv-cpu/blob/4f4580fa834ec9087a3487ec6cedbc55369773b0/scripts/run_ref_smoke.sh#L75)和[第 148—159 行](https://github.com/HakureiPOI/hias-riscv-cpu/blob/4f4580fa834ec9087a3487ec6cedbc55369773b0/scripts/run_ref_smoke.sh#L148)；[run_rtl_smoke.sh 第 54—69 行](https://github.com/HakureiPOI/hias-riscv-cpu/blob/4f4580fa834ec9087a3487ec6cedbc55369773b0/scripts/run_rtl_smoke.sh#L54)。

`run_ok`、`run_fail`、`observe` 都直接调用 Spike。RTL 的通用 `run_case` 同样直接执行，只有专门的 host-timeout-probe 套了主机超时。如果正常程序挂起、观察命令永远达不到 main，或仿真卡在一次 eval 内，后续探针和汇总都可能永远无法到达。单独证明 `timeout` 可用，不能证明正常验证入口有保护；C++ 周期计数也不能替代主机看门狗。

要求：为实际 RTL 仿真、断言探针和 Spike 正常/错误/观察路径统一设置可配置的有限主机时限，保留 RTL 周期预算。超时明确判失败，记录实际退出码，避免残留子进程。用受控挂起验证**正常执行路径及总入口**能够在有界时间内非零退出，不能只重跑另一个独立 timeout 演示。

### F02 构建返回码没有决定构建成功与否

位置：[run_rtl_smoke.sh 第 40—51 行](https://github.com/HakureiPOI/hias-riscv-cpu/blob/4f4580fa834ec9087a3487ec6cedbc55369773b0/scripts/run_rtl_smoke.sh#L40)。

`build_sim` 将 Verilator 的退出码写入日志后，最后只以目标文件是否可执行作为函数返回值。构建工具已经生成文件但随后返回非零，或清理失败残留旧产物时，调用方仍可能报告 build PASS。这与总入口“任意非预期步骤失败即失败”的约定不符。

要求：立即保存并传播真实构建退出码，只有本次构建返回 0 且产物存在时才成功；清理/目录准备失败也不能被忽略。补一个受控构建失败用例：即使目标二进制存在，只要构建过程非零，步骤和总入口就必须失败。建议使用隔离的工具包装器注入错误，不改正式 DUT 或正常测试期望。

### F03 负向探针未触发实际记分板的数据比较

位置：[tb_smoke.cpp 第 359—373 行](https://github.com/HakureiPOI/hias-riscv-cpu/blob/4f4580fa834ec9087a3487ec6cedbc55369773b0/verification/smoke/rtl/tb_smoke.cpp#L359)，对照[第 86—99 行](https://github.com/HakureiPOI/hias-riscv-cpu/blob/4f4580fa834ec9087a3487ec6cedbc55369773b0/verification/smoke/rtl/tb_smoke.cpp#L86)与[第 150—155 行](https://github.com/HakureiPOI/hias-riscv-cpu/blob/4f4580fa834ec9087a3487ec6cedbc55369773b0/verification/smoke/rtl/tb_smoke.cpp#L150)。

探针写入 `0x1111` 后调用 `pop_one(..., 0x2222)`。实际队列记分板仍期望 `0x1111`，因此其比较通过；报错来自 `pop_one` 额外的人工比较。原始 checker-probe.log 也只显示 `pop_one data mismatch`。这证明公共 check 函数能报错，尚未证明报告所称的记分板错误探针经过了真正的队列比较路径；该路径失效时，现有探针仍可能通过。

要求：在独立负向模式下，受控改变一次记分板期望或采样到的输出，使真正的队列比较报告具体 got/expected 不匹配。正常模式不得改动或降级；探针日志需能定位到记分板比较，不能由额外的人工错误保证“检测成功”。

## 4 非阻塞说明与范围调整

任务单要求一项深度缓存，实际交付是四项 FIFO。考虑到夹具仍保持小规模、用途仍是验证环境，本次接受四项夹具作为 P0-01 的范围偏离，**不要求为此重写 RTL**；opencode 应补记偏离，不能以后将该夹具当成已经验收的 CPU 公共模块。

Spike 使用 `-m128`（128 MiB），链接脚本只声明 128 KiB，当前程序实际使用地址均在链接区域内。这不阻断本次环境冒烟，但报告应区分两个容量；P0-02 必须统一 DUT 与参考模型的物理内存/PMA 约定，不能把当前参数直接当作最终系统地址图。
