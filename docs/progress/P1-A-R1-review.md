## 2 已接受部分

- **F01 的 RTL 修复关闭**：先验证 size，再要求 `RAM_BASE <= pa < RAM_END`，用剩余长度检查访问跨度；34 位顶端地址不再因加法回绕进入 RAM。size=3 使用 access fault。旧实现读/写别名及 size 原因码错误已有真实复现。物理尾字/保护字的修复后回读证据仍需按下一节补足。
- F02 已加入统一上升沿计数、运行中的周期预算、实际写事件输出、空闲观察窗口、Store+Flush 和两请求边界；接受这些实质改进，剩余项如下。
- **F03 的主机保护代码接受**：正常与负向执行均有有限 timeout/kill-after，比较步骤的预期退出码不匹配会设置总失败，忽略 TERM 的探针实际被 137 终止。尚缺“意外比较挂起令总入口 FAIL”的运行证据，见下一节。
- 核心仍为空闲骨架；Token 取消项+回绕联合用例保持通过。没有 CPU 执行、真实退休或 DiffTest/FPGA 声明。

## 3 验证收尾要求

### G01（中）：稳定性探针存在独立 ID 错误，成功标记可能假通过

定位：`verification/p1a/tb/tb_ram_bridge.cpp:580–583`；`logs/ram-stability-probe.log`。

探针使用 ID `0x52`，但接口只有 6 位，DUT 实际收到并返回 `0x12`。TB 却与未截断的 `0x52` 比较。日志同时记录真实的稳定性错误和 `response ID mismatch (0x12)`，最后 `errors=2`。日志确实证明本次触发过稳定性检测，但探针只以任意 `tb.errors>0` 生成 STABILITY_DETECTED；即使稳定性检测失效，另一个 ID 错误仍足以使探针报告成功。

修正为合法 ID，增加相同输入、fault_mode=0 的正常对照；错误探针的成功必须绑定专门稳定性错误及预期原因，不能由无关 ID/数据/超时错误代替。比较挂起探针的 `0x62` 同样超出 6 位，需一并改正。

### G02（中）：物理回读、最终握手稳定性与边沿守恒未闭环

定位：同文件 `118–123,282–290,417–428,462–499`。

- 新增“尾字保持”检查调用 `read_word()`，该函数只读参考数组 `mem`。非法请求本来不更新参考数组，因此这项比较不能证明 DUT RAM 尾字未变。应通过 DUT 正常 Load 回读尾字与相邻保护字，与独立预期比较；报告须区分参考值与 DUT 观察。
- held 响应只在 `resp_ready=0` 时和缓存比较，ready=1 的最终握手拍直接赋给 got，未要求其继续等于先前 held 值。握手发生的这一拍同样必须稳定。请求侧也应从上一拍是否 stalled 推导检查要求，不能在 ready 变高时先清监视状态。
- `pipeline_stall()` 走另一套手动计数路径，最后直接 `completed_count += 2`，并未由每个实际响应握手生成完成记录。它增加两笔 transactions，却不增加合法分类，因此当前 `629+773=1402`，与 1404 相差两笔。统一按采样边沿维护请求/响应参考队列和分类，驱动函数不能自行宣布完成数量。

用共用监视路径覆盖串行与 pipeline；对全部有效响应字段在最后握手拍也比较，并保留非法零写/合法一次写及无主响应检测。无需扩大并发能力，只修正测试观察。增加最后握手拍载荷被改变的受控反例，以真实检查器拒绝。

### G03（补证据）：专用超时探针通过不等于意外挂起令总入口失败

定位：`scripts/check_p1_a.sh:62–68,126–134` 与 `logs/ram-comparison-hang-probe.log`。

当前 comparison-hang 是独立的预期 124 探针，因此按设计被记为通过，总入口最后 PASS。该专用探针可以保留；它没有执行上一任务要求的另一项检查：让**原本预期比较失败 exit 1 的步骤**意外挂起，确认该步骤失败且 `make check-p1-a` 有界非零、汇总 FAIL。

代码路径已具备预期退出码不匹配的失败处理；本项不要求重构 runner。用受控命令包装或明确的测试开关，对原比较步骤注入挂起，保持其正常判据为 1 与比较错误原因；记录完整总入口命令、时间、退出码及 FAIL。证明超时不会被误判成普通比较失败成功即可。
