## 1 工作与验收

### V01：统一监视与失败判定

- 将正常与 initial_arf/hold_change 的观察值送入同一真实 ARF/保持监视器，再统一归类/判定。不能在注入专用分支重新做一次比较后直接打印 DETECTED 返回，绕过正常错误累计。
- 指定注入错误与其他错误分别计数；提交/镜像、fault 元数据/身份、禁止副作用、保持和预算等所有失败路径都纳入最终结果。仅当指定错误确实由真实检查器检出、其他错误为零、所需场景条件已完成时，才输出对应 DETECTED 并返回约定负向退出码。
- 目标未检出、出现额外错误、原因不符、场景未到达，应有可区分诊断/结果，runner 必须拒绝；已有 errors 不得被提前 return、复位或换阶段抹掉。正常关闭注入仍 exit 0。
- 故障分支明确核对实际正常提交数等于用例 commit_pcs.size()，Token 与预期前缀数量交叉检查。保留首次 fault 独立镜像正确性与正常 16 边沿保持；不要求为预期会立即失败的反例强行跑完 16 拍，但不得忽略检测前已有错误。

### V02：针对性反例与实际入口失败

- initial_arf、hold_change 各给正常对照、仅目标错误（认可检出）、目标错误加额外错误（拒绝认可）的证据。额外错误通过独立观察夹具制造，例如 fault cause 错误或非目标寄存器变化，经已有真实检查器检出，不直接调用 fail 或只打印失败文字。
- 给至少一类目标未检出/原因不符的对照，不能产生该类 DETECTED。打印目标错误、其他错误、场景到达/完成情况等实际统计；探针的预期失败判据保持固定。
- 至少一次完整 make check-p1-c：普通 fault 场景保持正常，只向原预期检出探针增加额外观察错误，原 runner 的成功判据不放宽，要求该负向步骤失败、汇总 FAIL、make 非零且时间有界。现有 fault_initial/fault_hold 对原正常步骤的失败证据保留，但不能代替这条“探针自身拒绝额外错误”的验证。
- 对 3ed8ec9 的“先有错误、仍 DETECTED/exit 1”给一次针对性复现即可，说明原 TB/观察夹具、命令、退出码和所掩盖的错误。无需重做旧 seq/快照盲点或早期完整 RTL 回归。
