## 1 修复与验收

### V01 / F01：真实握手、归属与迟到响应

- 仅在真实 valid&&ready 的边沿分配 owner 并保存身份；owner 非空时禁止第二笔总线请求被接受。未握手锁定 Fetch 被有效 redirect 取消后不能制造虚假在途项；明确取消例外与未取消时的完整 payload 稳定规则。
- 保存实际 req_id/gen，匹配且被消费的响应才结束原事务；错误 ID/代次的响应可以排空/报告，但不能释放原 owner、变更身份或完成另一客户端。正确响应后来到达应仍送回原拥有者并有界完成。
- 双客户端、无 owner/忙、同拍完成、锁定请求取消、reset 与请求/响应背压均遵守全局一笔限制；轮转/公平规则明确。前端与 LSU 本地身份检查保留。
- 至少动态复现 b42794c 的“错误响应后正确响应丢失”及“锁定取消时虚假 owner”，保存旧源/夹具、命令/退出码和逐边沿事件；修复后同场景通过。另覆盖 owner 忙时客户端提前持有后继请求而 bus_ready=1，不能产生未计入的接受。

### V02 / F02：统一边沿监视与独立记分板

- 从复位释放前建立统一边沿采样，显式初始化全部测试输入；响应完成按 valid&&ready，计入首次接受及最终握手，不通过给计数加常数修补。终点如有未排空取指，明确排空/取消及在途队列，不要求靠截断窗口凑相等。
- 每个 client 与 bus 维护已接受队列/身份、完整请求/响应 payload、接受/完成/实际写事件及退休对应关系；抓无主/重复/错路由/错身份/早写/重复写，实际写与成功 Store 一一对应。普通错误路径 Load 也不得悄悄发出；不能只比请求/响应总数或最终 RAM。
- 复用现有三个固定种子程序增加独立字节数组和逐笔检查即可，不要求另造随机框架；每种至少 200 笔数据事务。已知初始镜像/软件写入来自独立输入，byte array 不能从 DUT 结果自填期望。检查 raw Load、架构扩展、Store 标量和 lane，含 x0 Load。
- 完整 payload 稳定性涵盖最后握手拍；response 背压跨多个真实边沿，包装需暴露可检查的 payload。显式驱动 lsu_gate_i 和两端停顿；公平等待要有观测/预算。
- 覆盖新组合路径的取消 Fetch/迟到、错误响应后正确响应、无主/重复响应、缩小代次回绕；已接受 Load 取消与 Store+Flush 可复用真实组件夹具和 P1-A 桥，但须在本轮版本执行并标明覆盖边界。不要求给无投机 P1 后端新增投机取消功能。
- 给正常对照、一次真实事务比较/稳定性错误，以及目标错误加额外错误/目标未检出的拒绝对照。监视失败不能被后续 PASS 或目标命中覆盖，输出各类别实际统计与首差异。

### V03 / F03：fault 初值、完整保持和已知内存边界

- 使用独立已提交镜像，首次 fault **在再次 edge 之前**核对完整 PC/instr/cause/tval、Token idx/gen、从真实已接受 Fetch 得到的 fetch_gen、完整 ARF，以及无正常提交/Trap/非法写事件；继续 16 个真实边沿核对所有字段和无副作用，保存初值与保持事件日志。
- 对任何多余正常提交先范围检查，再索引期望表；不得以数组越界/崩溃冒充指定检查器检出。前缀数量与 Token 的期望仍独立核对。
- 补 RAM 最后合法 byte/half/word 的实际 LSU 读写、首个非法 byte/half/word，Load/Store 各类对齐/访问故障、真实 32 位 EA 回绕（例如 0xfffffffc+4→0，access fault），保留 MMIO access fault、x0 和桥错误用例。
- 明确初始化 RAM 保护字/比较区；定向 256B 比较可先全部软件初始化，或将比较范围改为已知 64B 并明确保护区；参考不能无来源填零。非法 Store 后直接读取生产 RAM 的安全观察或 DUT 正常 Load 回读均可，不只检查 TB 镜像。
- 新增经同一监视路径的首次 fault 禁止事件与身份/保持变化反例，证明它们会被拒绝；不直接调用 fail 或打印预定失败。沿用目标/其他错误分类与统一最终判定，不重复 P1-C 的早退问题。

### V04 / F04：真实失败传播与全部执行路径有界

- 删除“INJECT 非空就无条件 bad”；总入口只能根据原正常步骤/原预期检出探针的真实检查结果传播失败。当前 pc、probe-extra 两类错误路径保留，同一固定判据，不放宽。
- nm 终点发现优先解析已受保护并保存的 nm 输出；所有实际构建/生成/观察/正常与负向执行均有主机 watchdog+kill-after、真实退出码检查。校验 timeout/kill-after 与开关参数，不能把未知开关当作已执行场景。
- 给一次终点发现或生成命令受控挂起的实际总入口证据，内部自行有界 FAIL，外层宽限超时不触发；保留构建非零即使二进制存在也拒绝。
- 正常对照与 pc/probe-extra 实际总入口失败均在同一实现提交执行；再选择一个本轮新增访存/故障监视错误通过实际入口证明不能被吞掉，日志可追溯到具体真实失败类别。
