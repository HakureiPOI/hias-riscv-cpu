## 1 范围与阅读

阅读设计书、P1-A/B/C 模块说明、ISA/地址图、共享类型/接口、hias-retire/2 和前述管理验收。先梳理 frontend/core/top/bridge/TB/差分适配调用者与时序，再实现；不能在 TB 解释执行或另写独立 CPU 冒充集成结果。

在 P1-C 29 条基础上新增 LB/LH/LW/LBU/LHU、SB/SH/SW，共 37 条正常指令。保持单活动槽、单条后端指令在途；无乱序、Cache/MMU、CSR/Trap、M/A/C/F、FENCE/FENCE.I 或 FPGA 扩展。合法未实现系统指令继续明确停止，不静默跳过。

本轮只实现 RAM 数据访问。UART/test_result 的真实外设、板上物理串口与完整启动/终止协议留给 P1-F/G，课程要求不删除；当前未实现的 MMIO/保留地址应产生数据 access fault。P1-D 仍须遵守未来 MMIO 只能在提交头发请求的规则，不把任意 MMIO 当 RAM/返回零。

## 2 实施要求

### D01：LSU、状态和退休

- EA=(旧 rs1+符号扩展立即数) mod 2^32；Bare PA 为 EA 零扩展到 34 位。保存原 PC/instr、EA/PA、宽度、读写、标量数据、Token/fetch_gen，直到完成/停止；rd=rs1 和 Store 源重叠使用接受时的正确旧值。
- 复用 mem_req_t/mem_resp_t。mask 指四字节字内 lane，wdata 为截断到 8/16/32 位的低位标量，不左移；桥返回低位零扩展原始读值，LSU 对 LB/LH 做符号扩展，LBU/LHU 零扩展，LW 原样。不要对桥已提取的数据再按 lane 移位。
- Load 仅在合法匹配的成功响应后完成，ARF 仅在真实提交边沿写入；Load 到 x0 仍需执行访问并产生应有故障。Store 不写 ARF，成功响应后恰好退休一次。退休前不得接受下一条后端指令。
- Store 请求必须获得唯一顺序提交槽的头部授权，检查通过后才发送；请求接受到成功响应/退休构成不可取消事务。物理 RAM 写可早于退休，但不得因背压重复写、因普通 Flush 取消或重发；失败 Store 不能先写后报错。不要求写事件与退休同拍。
- 正常退休真实携带 mem_valid/we/va/pa/size/mask/wdata/rdata，遵守冻结有效/null/数据语义；Store 无 rd 写，Load 数据等于架构结果；普通 ALU/分支 mem_valid=0。seq 只由真实退休事件递增，不由请求或响应数生成。
- 不对程序数据区偷偷复位为已知值：软件或静默镜像明确初始化使用区域；保留平台生成布局。测试结束的 RAM 快照只观察，不改写 DUT。

### D02：取指/数据仲裁与身份

- 现有前端取指与新 LSU 共享真实 RAM/桥，明确每个请求的拥有者和锁定时点。允许保守地全局只一笔已接受事务；记录仲裁规则、请求/响应保持以及有限服务保证。
- 仲裁输出 valid 且未 ready 时完整 payload 和拥有者必须稳定，不能因 LSU 到来切换被阻塞取指；响应背压时也保持完整载荷/路由。只让被选中发送者见 ready，响应只能送至原拥有者，不能广播或靠地址猜路由。
- 从真实边沿记录接受、完成、实际 RAM 写和每个客户端的顺序队列；恰好一次、无重复/无主/错路由，最终完成数与接受数守恒（取消项按明确排空规则核算）。覆盖 frontend 已有在途响应时 LSU 到达，避免前端等后端、数据等前端形成死锁。
- 响应校验已接受事务的 ID/代次等冻结身份。取消取指/可取消 Load 的身份保留到响应排空；迟到响应不能写 ARF或复活已取消项。Store 接受后不能当作普通年轻 Load 丢弃。跨客户端 ID 可重用时须说明拥有者隔离，回绕前禁止与未排空身份别名。
- 提交分支 redirect 仍只清年轻项，保留自身结果；错路 Load/Store 不产生数据请求/写事件。使用真实前端错路片段验证，不只对独立 LSU 拉 Flush。组件级夹具另覆盖已接受 Load 取消/迟到、已接受 Store 遇 Flush，以及缩小代次回绕。
- reset 在核/仲裁/桥共同复位下定义；列明在途事务清空和 RAM 保持规则，不允许复位后旧响应匹配新请求。不得拿 reset 撤销已发生的写副作用；普通 Flush 与 reset 分开说明。

### D03：访存故障停止

- 本轮采用先自然对齐检查、再 RAM/PMA 访问检查：非对齐 LH/LHU/LW 为 cause 4，SH/SW 为 cause 6；对齐但 RAM 之外/桥访问失败为 Load cause 5、Store cause 7。tval=原 EA，fault PC/instr/Token/fetch_gen 对应该指令。
- 接受数据请求之前拦住可预知的非法请求；桥返回错误仍必须处理。失败 Load 不写 ARF，失败 Store 不改变 RAM，不产生正常退休或假 Trap；fault 之后停止并保持元数据及完整架构状态，等待未来 P1-E。
- 必要时扩展当前 held fault 类别位宽/结构以区分数据异常，更新所有调用者/夹具；不能把数据故障标成合法未实现指令。共享冻结契约的必要变更列原因与影响，不静默改变既定字段语义。
- 原 P1-C 用 LW 作为未实现停止用例在支持 LSU 的路径上已过时，须显式替换为仍未实现的合法 CSR/系统指令，或保留原无 LSU 配置进行旧入口回归；说明用例变化，不能保留假停止或删除整类边界检查。

正常流和故障流分开：Spike 对非对齐访问的执行环境策略不作为本轮 cause 4/6 的隐含参考，故障停止用冻结规则/独立期望，不要求已实现 Trap。Spike 不能观测的 Token 只做 DUT 身份检查；Bare 内存地址/宽度/掩码/扩展结果可从原指令/参考日志推导，明确来源。Store 标量与 raw Load 及架构扩展值分别核对，不能只比较最终内存签名或只验证格式。

可用普通 RAM 预定终点/退休预算结束，终点指令不能被丢弃来对齐参考；不依赖尚未实现 ECALL/EBREAK/CSR/HTIF 或 MMIO 作为 DUT 成功退出。参考模型启动/终点与未知初值显式对齐，沿用严格格式门禁与基线先验检查，不过滤失败 DUT 记录。
