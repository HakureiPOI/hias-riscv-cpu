## 2 必修项目

### F01 正常路径看门狗

- 对实际 RTL 正常仿真、断言探针、Spike 正常/错误结果运行和观察命令都使用可配置的有限主机时限，RTL 自身周期预算保留。
- 超时不是正常通过。记录原因与实际退出码，确保必要的终止/清理机制有界，不能留下持续运行的子进程。
- 保留专用超时探针，但增加对正常执行路径的受控挂起验证：在实际 runner 中让正常目标挂起，检查该步骤和总入口在合理期限内非零结束，并输出超时原因。
- 普通功能验证超时与“预期超时探针成功”明确区分。不得把任意 124 或任意非零退出都当成探针成功。

### F02 真实构建失败传播

- 构建函数立即保存真实退出码并据此返回；本次退出为 0 且预期产物存在才算成功。目录清理/创建失败不能继续使用旧产物并报绿。
- 补受控构建失败探针，覆盖“二进制存在但工具返回非零”。隔离的工具包装器可以完成注入；不要改坏实际 RTL 来伪造构建问题。
- 证明真实构建失败会使步骤和总入口失败，即使其他测试本可通过。日志写出真实构建返回码以及由哪个步骤传播失败。

### F03 真正的记分板负向检测

- 负向模式只对一次队列期望或输出观测做受控错误注入，经过正常记分板比较路径报告 got/expected 不匹配。
- 不再依靠 `pop_one` 的额外人工不相等检查保证检测。正常模式仍使用独立队列和原有功能判断。
- 若探针没有产生预期的记分板错误，负向探针验收本身应失败；只有预期错误源、退出码和消息对应时才算探针成功。
