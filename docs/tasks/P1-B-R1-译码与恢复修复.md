## 1 修复要求

### F01：修正 JAL 与独立期望

- JAL opcode 下按 J-type 取立即数，不对 `instr[14:12]` 检查 funct3。保留 JALR 与其他实际存在的功能码检查。`0x000010ef`、`0x000012ef` 必须分别合法译码为 JAL x1/x5，imm=+4096；修正 `JAL_neg` 与错误命名的 `ILL_JAL_F3`。
- 同步修正生成器/生成表，并增加明确的规范锚点：对关键编码以手工核对字段的固定期望断言，结合锁定工具链 assembler/objdump 的编码/反汇编留证，不能只复制 RTL 条件再宣称独立。无需接入新参考模型或执行程序。
- 覆盖 J-type `instr[14:12]` 全部 8 种值、正负偏移、0、+2、-2、-4、+4096、最小 -1048576 与最大 +1048574，以及 rd=x0/x1/x5/x31。全部合法编码的 imm/is_jump/rd_we/操作分类正确；偏移 +2 是合法编码，执行时目标对齐检查留给后续执行阶段。
- 原 40 条、六种 CSR、HINT/Fence 忽略字段及非法编码覆盖保留，表项数按真实新增结果更新，不保留错误“非法 JAL”凑数。独立译码单元和实际 RAM 前端都要看到修正后的样例。

### F02：生效重定向与响应身份闭环

- 明确有效、对齐 redirect 的统一生效条件；同拍清除/抑制外部译码 valid 与接受，`decoded_o.valid` 与 `decoded_valid_o` 按接口保持一致。消费者可以持续 accept=1，生产者必须自行满足取消契约，TB 不能靠 redirect 时主动 accept=0 掩盖问题。
- 每个已接受请求保存 PC、ID、代次；取消项仍保留该身份。错误 ID 或错误代次响应可以按文档丢弃/诊断，但不能释放真正待完成请求、解除回绕屏障或生成结果；只有实际握手且身份匹配的终结响应才能排空。连续 redirect 更新新目标而不覆盖在途身份。
- 非对齐目标报告协议错误，不更新目标 PC、不伪造 Trap；其与待响应/已保持输出同拍的行为应一致、明确，不能将被拒绝的 redirect 当作有效取消来丢失结果或提前释放身份。
- 定向测试至少包括：旧译码 valid 保持、accept=1 与合法 redirect 同拍；redirect 与匹配响应同拍；取消后错误 ID、错误 gen 分别先到而真正响应延迟多拍；缩小 GEN_W 下最后代次请求取消、错误响应到达、真响应排空后才回绕；连续 redirect；非法目标与在途响应同拍。逐拍证明 pending、输出与下一次实际请求接受符合契约。
- 默认 GEN_W=8 和强制回绕配置均完成适当编译/检查；故障注入留在 TB 包装，ID 不超冻结 6 位。保持 P1-A RAM/桥生产逻辑，不为测试制造假响应修改它。

### F03：累计失败、统一监视与正常入口拒绝反例

- 全程累计错误/失败状态不得在阶段、复位或种子切换时清除。阶段统计使用独立增量；每阶段 PASS 标记受该阶段真实结果约束，总 PASS/exit 0 受全局结果约束。每种子各完成至少 340 次接受，三个固定种子保留，总数至少 1020，不能用后两种子合计替代前一失败。
- 所有工作边沿，包括同拍重定向、故障注入和非法目标测试，统一进入请求接受、响应接受、译码接受与稳定性监视。使用独立在途队列/记分板匹配 PC、请求身份、返回字/异常、预测占位与 fetch_gen；区分无主故障响应和真实事务完成，不能把任意响应总数相等当成所有权正确。
- 请求与译码载荷在背压期间及最终接受边沿均逐字段保持；覆盖本阶段所有有效字段，注明无效字段的比较规则和合法取消例外。保留相邻握手、非法/取指故障区分、无重复/丢失、禁止 RAM 写和禁止伪退休检查。
- 复位前通过门控停止新请求并排空已接受事务，队列为空后才复位；全局失败不清除。报告每阶段/每种子与全程统计，手动时钟路径不得漏计。不要把未排空事务随复位删除而宣称守恒。
- 新增两个受控反例：在正常完整流程的定向阶段、首个随机种子分别让一个真实比较期望错误，随后恢复该期望，继续后续正常阶段。最终可执行文件必须仍非零，错误类型必须是该比较；正常关闭注入的同流程通过。保存至少一项实际 `make check-p1-b` 在该注入下自行汇总 FAIL/非零的日志，不将预期失败改成总入口成功。
- 保留既有真实字段负向及 124/137 看门狗，负向成功只能绑定指定错误原因，不接受超时/任意失败代替比较检测。全部入口仍有有限主机看门狗、kill-after、周期/事务预算及真实构建退出码传播；注入运行与正常运行分目录。
