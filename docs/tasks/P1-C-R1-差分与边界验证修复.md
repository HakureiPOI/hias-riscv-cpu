## 1 修复与验收

### V01 / F01：完整消费 DUT 与实际字段比较

- 差分器必须消费并校验整个 DUT 文件，不在首个终点 PC 后静默 break。约定恰好一个末尾终点退休，拒绝其后的任何额外正常记录/Trap/坏行；最终 count 与全部输入记录一致。seq/Token/来源/有效性等格式检查纳入同一可复用入口，不靠调用顺序偶然保护。
- 比较真实 d.priv 与参考，其他被声明逐字段比较的值也来自实际输入，不以常量替代。TB 可保留端口 M 检查，序列化按实际观测值映射。
- 参考有限运行与终点裁剪规则明确区分于 DUT：允许有界 Spike 在终点自循环后正常退出，但说明并验证参考后缀规则；不能将任何差异路径随意截掉来迎合 DUT。最后一条 DUT next_pc 的参考来自实际后继 PC/调试终点观察，标为 derived，不把命令行 end_pc 参数当快照。
- 最终寄存器可由完整参考提交写日志重建，但必须如实说明来源；提交终点 PC、提交后 next_pc、退休数量分别核对，不能混称。保留 hias-retire/2 与 DUT/派生来源边界。
- 正常对照通过；从实际正常 DUT trace 构造额外尾记录（终点重复和非终点各一）、终点后的坏行、删除/重复中间记录、priv 改为 S/U、末条 next_pc 错误等正反例。追加正常记录要保持 schema/seq/Token 合法，证明是完整消费/差分检查拒绝，不仅是格式碰巧出错。

### V02 / F02：干净基线与指定错误原因

- 所有 --inject 模式先完整验证未修改基线，包括全量 DUT 文件、参考对照、终点/最终寄存器/数量和 Token。基线坏时返回基线失败，不打印该注入的 DETECTED。
- 注入副本后，只能由指定字段/位置或数量关系的真实检查失败产生该类成功标记。区分目标错误、无关/额外错误、未检出；不能捕获任意 DiffError 后贴上用户指定 kind。保持首差异详情，必要时先独立检查非目标约束，避免额外错误被首个预期错误掩盖。
- pc/instr/rd/next_pc/missing/duplicate/token 七类均纳入实际总入口并留证；计数和报告按真实执行更新。rd 选择实际写回记录，missing/duplicate 的预期为记录数/结构差异，Token 注入同样需要干净架构基线。
- 正常对照、仅目标错误、基线已有无关 PC/数据错误、目标错误伴随另一无关错误分别验证。后两者不得算该类检出成功。保留实际总入口对原正常步骤注入后自行 FAIL/非零，至少再保存一项原因不符/额外错误导致实际总入口失败的证据；不把超时视为比较成功。

### V03 / F03：真实恢复、停止与边界

- 为整数集成提供测试专用请求门控/观察：桥和核心两侧对同一真实握手达成一致，生产 RAM/桥不改功能。安排一条实际已接受的控制转移在提交时遇到年轻取指请求 valid=1、ready=0；检查该未接受请求取消、正确目标后续执行、原跳转自身退休/链接写保留、错路不退休。不能用外部人工 redirect 代替真实后端提交。
- 分别补/确认已接受响应在途、匹配响应同拍、译码结果被保持时的真实恢复；覆盖条件来自明确握手与在途/保持身份。对齐原四类语义，后端 accept_stall 单独统计，不能与请求等待混用；每场景输出触发前后事件/身份与结果，不仅给非零总数。
- 故障观察改为推进实际时钟边沿；首次 fault 后继续至少 16 个工作周期，核对完整 fault kind/PC/指令/cause/tval/Token/fetch_gen 保持、无额外正常提交/Trap/ARF/实际 RAM 写。用已提交前缀的独立 ARF 镜像检查所有寄存器，不限于初始全零；正常提交的最后一条也必须完成实际写边沿再判定。
- 增加 JALR 清 bit0 后 bit1 仍置位的非对齐用例，带非零旧 rd、已提交前缀，检查不写链接、cause=0、tval=清 bit0 后目标、fault_pc 为 JALR PC。保留 JAL/taken 分支异常、untaken 同目标不异常、正常 JALR bit0 清除及 rd=rs1 的对照。
- ALU 单元增加明确的 sign-extended imm12=-2048/-1/2047 等 32 位值，LUI/AUIPC 高位/回绕、移位 0/31/高位截断锚点；区分合法 ISA 输入与额外 ALU 运算测试。六种分支各给 taken/untaken 覆盖矩阵，由真实集成执行留证，不能只宣称随机数足够。
- 新监视器给正常对照与至少一条真实副作用/保持/错路检查路径的受控负向，绑定原因，防止只加成功打印。观察夹具可注入故障，不向生产 RTL 添加错误分支。
