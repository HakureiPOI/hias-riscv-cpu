## 1 工作与验收

### V01 / G01：所有差分模式复用完整格式校验

- 将现有 hias-retire/2 读取/validate_stream 等通用函数接入 p1c_diff 的公共输入/基线路径，正常、七类注入和 pc_extra 都走同一门禁。保留独特的 P1-C 子集、Token/终点与 Spike 对照约束，避免格式校验重复实现而逐渐分叉。
- 覆盖 seq 严格递增、必需字段、布尔/数值严格类型、有效/null 与 derived/not_observed 来源列表等既有冻结规则；不放宽共用校验器以适应错误输入。不需要改变协议或新增字段。
- 从真实正常 trace 构造仅 seq 重复/倒退或缺失、有效位用字符串/数值替代布尔、字段缺失/类型错误等代表反例；正常对照通过。直接调用差分器，无需先运行外层格式命令，必须统一拒绝；加 --inject rd/token 等也应先返回基线格式失败，不打印注入 DETECTED。格式错误诊断清楚、退出有界，不能只依赖 Python traceback。
- 可保留正常总入口原格式步骤作为显式证据；该步骤存在不能代替差分器公共入口校验。现有尾记录/priv/next_pc/脏基线及七类指定原因、额外错误反例继续通过。

### V02 / G02：独立已提交镜像与 fault 初值

- 在 fault TB 从确定的复位状态维护独立 32 寄存器镜像，仅按真实正常提交在实际边沿更新。每个提交写与原用例/程序预期一致，x0 恒零；不得在 fault 到来时从 DUT 读回整套寄存器作为正确性期望。
- 首次 fault 时立即核对全部 ARF 与此前已提交镜像，之后至少 16 个工作边沿继续核对不变、无额外正常退休/Trap/实际 RAM 写。所有零前缀与非零前缀停止场景均覆盖；首次错写不能被吸收进快照。
- 特别校验 jalr_unaligned：两条前缀提交后 x1=0x55、x5=7；故障 JALR PC=0x80000008、cause=0、tval=6，x1 仍为 0x55，不能变成链接 0x8000000c。正常 JALR 对照完成实际提交边沿并保留正确链接。
- fault kind/PC/instr/cause/tval/Token 的初值按用例与真实分配序列核对；fetch_gen 按可观测生产者身份验证传递。用于保持检查的首次快照可以保留，但不能代替初值/前缀正确性期望。
- 给统一、可追溯的正常提交、fault 首次到来及 16 边沿日志，说明镜像推进和实际 ARF 比较位置。保持本轮已测时序，文档同步实际 S_EXEC3 状态；不为本任务重排执行流水。

### V03：监视器受控负向与实际总入口失败

- 使用独立测试观察包装/夹具制造两类反例：首次 fault 被观察到时 ARF 已错误（例如 x1 为链接值），随后 16 拍稳定；以及 fault 保持期间出现一次 ARF/元数据变化。关闭注入的同流程正常通过。
- 前者必须被独立已提交镜像拒绝，后者必须被真实保持/副作用监视拒绝；不能通过改打印、直接调用 fail 或以无关比较错误冒充。指定错误类别计数与其他错误隔离，探针只在预期检测实际发生且没有其他错误时认可；未检出/错误原因不符必须拒绝。
- 至少一项对原正常 fault 步骤注入的完整 make check-p1-c，自行汇总 FAIL/非零并有界退出；不得把整个正常步骤改为预期成功来迎合注入。正常与预期失败运行分目录，保留看门狗/kill-after、周期/退休预算、真实构建退出码及 pc/pc_extra 的既有失败验证。
