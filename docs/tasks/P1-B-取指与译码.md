## 1 阅读与范围

阅读本任务、P1-A 验收、设计书、ISA/CSR/地址图、共享类型和接口。复用已经验收的 RAM/桥、主机看门狗、报告/证据流程；不重做环境或存储框架。

本轮新增实际前端 RTL，不在 TB 内实现功能来冒充前端。按 Fetch→Decode→译码结果保持的分层留出 P1-C 接口；不实现 ALU/分支执行、LSU、CSR 状态更新、ROB/IQ、BPU/Cache/MMU/FPU、退休或 DiffTest。P1-C—F 再逐步接入后端。真实 RAM 中取到指令字不表示程序已执行。

## 2 实施要求

### B01 单活动槽取指

- 复位 PC=`RESET_VECTOR`，M-mode/Bare，无 C，顺序候选 PC 每条加 4。使用 `mem_req_t`/`mem_resp_t`：word 只读、PA 为 VA 零扩展到 34 位、mask=0xF、Store=0、wdata=0，ID/代次有明确分配与匹配规则。
- 首版最多一个外部请求在途，允许额外一个结果保持寄存器；无数据覆盖或无界取指。P1 输出活动槽仅 S0，公共 bundle/反向 prefix_accept 类型仍保留两槽结构；S1 无效且 count 不得超过 1。
- 请求未接受时保持 valid/payload；响应与译码输出均支持背压。只有真实握手才前进，输出被阻塞时保存 PC、指令、预测占位、异常和代次。不能用单拍脉冲丢指令。
- 无 BPU 时明确顺序预测占位（pred_taken=0、pred_target=PC+4、pred_index=0），不称预测器已实现。独立 Decode 单元仍保留任意输入预测元数据，不在译码时重新生成覆盖。
- redirect/flush 优先于同拍正常输出/接收。尚未接受的请求按取消契约撤销；已经接受的读必须收尾，旧响应不得产生新译码事件。保存请求原 PC 和身份，不能把响应归到重定向后的 PC。
- 至少覆盖重定向发生于请求等待、响应等待、译码背压以及恰逢响应的同拍。连续重定向不能复活旧项；代次回绕前排空仍可返回的事务，缩小代次参数强制覆盖。有在途旧响应时不能因代次再次相等而误认新响应。
- 不匹配 ID/代次的响应不能写输出；给出丢弃/诊断策略并测试随后真正匹配的响应仍能完成。真实 RAM 桥保证每请求一次响应，故障注入响应由独立包装提供，不修改生产桥造错误。
- 取指访问错误转换为 `fetch_exc_valid`、instruction access fault(1)、tval=原取指 PC；错误返回值不能同时被当作非法指令。异常槽稳定保持、交付一次，之后等待 redirect，不继续生成无限异常流。真正 Trap 留给后端。
- 正常 redirect target 需 4 字节对齐；跳转目标非对齐的架构异常由未来执行单元在原跳转指令处产生。前端对违反该接口前提的输入做受控协议检查，不伪造具有错误 EPC 的 Trap。

### B02 译码

- 用冻结 `decoded_slot_t`、`op_class_e`、`exec_op_e` 表达 RV32I 40 条（含 FENCE/ECALL/EBREAK）、六种 Zicsr、Zifencei、MRET、WFI。P1 不支持的 M/A/C/F、SRET/SFENCE.VMA 等按冻结范围标非法；CSR 地址权限/写合法化在 P1-E 检查，本轮不假装读写 CSR。
- 明确 rd/rs1/rs2、uses_rs1/uses_rs2、rd_we、立即数、访存宽度/符号操作、CSR 操作/五位立即数以及各系统标志。移位立即数只将 shamt 五位作为运算量，I/S/B/U/J 立即数按语义扩展；说明编码与后续消费者约定。
- rd=x0 不产生架构写使能，但 Load x0 仍保留访存/故障属性；合法 HINT 不因没有寄存器写入而被判非法。CSRRS/CSRRC 的读不能由 rd_we=0 抑制，完整原指令和立即数标志须保留。
- 检查 opcode/funct3/funct7 与保留编码，尤其 JALR、branch/load/store 的非法 funct3、OP/OP-IMM 移位组合、RV32M 编码、非法 SYSTEM；非法指令保留 32 位原编码作 tval。不要只比较 opcode 后把整类未知编码当成合法 ALU。
- FENCE/FENCE.I 的未用字段按基线规范忽略，不将非零 rd/rs1 等一概判非法；保守 FENCE 分类不承诺特殊扩展。依据 [RV32I](https://docs.riscv.org/reference/isa/unpriv/rv32)、[Zifencei](https://docs.riscv.org/reference/isa/unpriv/zifencei.html) 的前向兼容规则，核对锁定 v20260120 并给表格示例。
- Fetch 异常优先且元数据完整传递；仅当取到有效指令字时才作编码非法判断。PC/原指令/预测索引/异常 cause/tval/代次等逐字段给生产者→保存位置→消费者映射，不因两级拆分丢失信息。

### B03 集成与测试观察

- 至少交付前端 + 已验收 RAM/桥的实际集成 TB，镜像在取指启动前静默载入；按地址从独立镜像取得预期字，不用 DUT 输出生成期望。给文件列表、端口和 P1-C 接入位置。
- 可以保留原 SoC 空骨架测试，再独立集成可复用前端；若接入 SoC，则无后端消费者时必须保持译码结果并停止，而非无条件丢弃以维持取指。不要破坏原空闲测试的含义来获得回归成功。
- 译码输出由 TB 模拟消费者按反向 count 接收，属于模块观察，不是架构提交。所有 commit/Trap 端口仍不产生真实事件；取指/译码日志使用明确名称，不能包装为 hias-retire 的 DUT 记录。
