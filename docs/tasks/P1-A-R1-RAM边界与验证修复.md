## 1 修复与验收

### F01 / V01：范围与非法编码

- 先在独立目录对旧实现 `afbb11d15094e234c1c9c1eda78d40dacf83cc2a` 复现顶端 PA byte/half/word 的读/写；保留具体请求、错误位、数据/内存观察及真实退出码，不能重写历史证据。
- 修复端点回绕：完整 34 位 PA、有效 size、起止和整个访问跨度均正确，不截高位；可用扩位算术或安全剩余长度，不只补一个特例地址。
- `0x3ffffffff` byte、`0x3fffffffe` half、`0x3fffffffc` word 的 Load/Store 均须 access fault，ID/代次正确；错误写不能碰 RAM。预置 RAM 尾字/相邻保护值，非法请求后读回一致。
- 保留 RAM 首末正常 byte/half/word、越界、MMIO、高 PA、掩码/数据错误测试；补 size=3，按接口非法请求报告 load/store access fault。只有有效 size 的非对齐访问使用 misaligned cause。独立模型不得复制 RTL 的有限位宽溢出。

### F02 / V02：真实边沿监视与数据副作用

- 统一时钟/边沿采样函数，周期覆盖初始化与全部事务，分段计数可以另列；总周期预算在运行中到限立即失败。合法/非法/请求接受/响应接受/实际 RAM 写入分别统计。
- 独立请求/响应记分板：只按握手入队出队，检查 ID/代次、数据/错误、顺序、每请求一次响应；无主/重复响应失败。握手后留明确空闲观察窗口，不让下一事务掩盖额外响应。
- 响应背压期间，从首次 valid 开始逐拍检查 valid 和完整有效载荷稳定；请求保持 valid、payload 遇 ready=0 时同样检查。等待请求必须是在上一事务/响应阻塞时实际呈现，不能只延迟 valid。覆盖旧响应消费与下一请求接受的同拍/相邻拍边界，允许保守停顿。
- 将实际 RAM 写接受事件暴露给 TB 或用等效断言监视，与独立模型的合法性和 Store 接受记录匹配。每个合法 Store 一次实际写；非法请求零次，不能用幂等写掩盖重复副作用。关键别名位置以正常读取复核。
- 补未接受请求遇 Flush、已接受 Load+Flush、已接受 Store+Flush，含响应背压，核对完成一次与 Store 数据保持。复位/加载维持静默前提并写清，不新增并发加载能力。
- 至少一条受控反例让新的稳定性/守恒检测器失败，例如 held 响应改变后恢复，或重复响应；只能走真实新检测路径，不能直接打印错误冒充检出。
- 三个既有固定种子及原定向项保持；统计按修复后真实执行结果填报，不要求保持原 1392/34124 数字。Token 取消项+回绕联合补测保留，已接受结论不重开。

### F03 / V03：所有负向路径的有界执行

- 正常、比较负向、时序反例和挂起/观察命令均由有限主机看门狗执行，有 kill-after 强制终止；配置时限有明确单位并拒绝无界/非法值，沿用已有工具版本。
- 预期比较失败须核对真实比较错误与其退出码；超时、构建失败、缺失二进制均不得被当作该探针成功。
- 受控挂起覆盖比较负向入口和专用 timeout 入口；包含忽略 TERM 的子进程场景。步骤和 `make check-p1-a` 都应有界非零并记录实际用时/退出码；意外挂起不能使总入口 PASS。
- 正常比较负向仍按明确比较原因退出 1；专用超时探针按所选工具的实际超时/强杀码核对并解释。回归保留构建返回码立即传播，不运行失败构建的旧产物。
