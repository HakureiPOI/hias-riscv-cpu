### F02 / V02：Token 和通道夹具

保持小型契约夹具，不实现 ROB。先记录旧实现对复审反例的实际结果，再修复；反例不能被删除或改成允许错误结果。

| 场景 | 必须观察的结果 |
| --- | --- |
| 分配→Flush→重新分配→旧响应 | 旧响应不能完成新事务；身份不在仍有旧响应的窗口复用；取消项在外部完成/确认前保留在途记账 |
| 有两项在途，一分配与一完成同拍 | 在途净数量不变，集合正确；不以两次赋值相互覆盖 |
| 多项分配，非队头响应先到 | 不覆盖仍活跃项；若是顺序回收模型，明确完成和回收的区别 |
| 回绕但有未完成/取消事务 | 停止新分配且不能提早解锁；真正排空后恢复；缩小 GEN_W 强制覆盖 |
| Flush 与完成/分配同拍 | 外部接受信号与优先级一致；没有被清除项复活、遗漏在途事务或重复完成 |
| 双槽部分接收和背压 | 定义边沿接受谓词；使用发送端待发送队列及接收端记分板，检查 S0/S1 恰好一次、次序和稳定性，不能只验证组合 accept_count |
| 第二槽异常 | 最小事件夹具检查 S0 先退休、S1 下一拍 Trap；同拍退休/Trap 互斥，异常元数据不丢失 |

建议用独立在途 Token 集合检查忙项数、身份和接收/丢弃结果；不要仅复制被测状态更新作为预期。允许保守阻塞，不要求同项零气泡分配或优化性能。复位时外部请求的处理同样要有明确环境契约，不能假定内部清零等于外部排空。
