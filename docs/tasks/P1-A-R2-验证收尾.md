## 1 工作与验收

### V01：探针只因指定错误通过

- 将稳定性探针及比较挂起探针的 ID 限制在冻结的 6 位范围；统一检查驱动参数合法性，避免静默截断制造其他错误。
- 相同请求在不注入故障时正常通过；注入 held 响应变化时，由真实稳定性检查器检出。单独统计预期稳定性错误，成功标记只能由该错误产生，其他错误必须导致探针自身失败。
- 保留真实比较负向，绑定比较错误而非任意 errors>0；核对退出码和原因。不要直接打印错误替代检测，也不把超时归为比较/稳定性成功。

### V02：物理观察和统一边沿监视

- 顶端非法 PA 与非法 size 请求后，通过 DUT 总线正常 Load 回读尾字及相邻保护字，对照明确预置的独立期望。日志给出地址、DUT 值、期望和结果；参考数组自读不能作为 DUT 回读。
- 将串行 transact 与 pipeline 测试都接入同一采样/监视路径：每个请求接受和响应接受由实际 valid/ready 边沿生成，参考队列按顺序进出；禁止手动 `completed_count += 2` 宣布通过。
- 响应若前一拍 valid 且未 ready，本拍必须保持 valid 和完整 payload，包含本拍 ready=1 的最终握手；请求侧同理，明确 Flush 取消尚未接受请求的例外。
- 补最后握手拍载荷变化的受控反例，使用同一真实监视器拒绝；正常对应场景通过。既有 held 多拍变化负向仍须有效，原因分别清楚。
- 保留无主/重复响应、非法零写/合法 Store 一次实际写、Store/Load+Flush 和周期预算检查，所有实际边沿计数。正常结束时分类合计=事务接受数=响应完成数，队列为空；写事件数与预期一致，打印真实统计。
