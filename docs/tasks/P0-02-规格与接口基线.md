## 1 工作边界

本轮完成细化规格、共享配置/类型、接口时序和测试计划，并在容器中验证类型、配置及工具入口。尚不实现 Fetch/Decode/ALU/ROB/Cache/MMU/FPU 等处理器模块，不把规格草案或类型包称为 CPU 已支持相应功能。

阅读 README、协作流程、设计书、课程要求、调研记录、P0-01-R1 报告与管理验收。使用既有环境与 runner，保护现有工作，不重做环境；发现设计书、规范或参考模型冲突时提出定位、证据与建议，不自行削减课程要求。

## 2 ISA、CSR 与异常范围

交付 `docs/architecture/isa-support.md` 与 `docs/architecture/csr-support.md`。

- 把“P1 最小核”“后续集成阶段”“最终承诺”“暂不支持”分开，逐类列出 RV32I/M、Zicsr/Zifencei、特权指令与异常；全部标明这是计划能力，当前 CPU 未实现。
- P1 按设计书建立 RV32I 基线和最小 M-mode Trap/CSR 能力；最终保留 RV32IM、Zicsr、Zifencei、M/S/U、Sv32 与 Svade 的目标，不把所有系统功能都推迟到 P5 才设计。
- 明确非法指令、非对齐 Load/Store、跳转目标非对齐、ECALL/EBREAK、访问故障、Page Fault、异步中断的 cause、EPC/tval 规则、处理阶段及目标阶段；区分异常事件和正常退休。
- CSR 表至少包含地址、权限、读写/别名、复位值、实现位、WARL/WPRI/只读位、CSR 指令读写抑制规则、P1/最终阶段。覆盖设计书第 6.4 节已列寄存器，并说明计数器、身份寄存器、未实现地址与保留位的处理。
- 明确提交槽异常优先级、CSR/Fence/返回的串行与年轻指令清除规则、外部中断输入的挂起与响应边界。对本阶段尚无运行证据的特权行为标明“规格待实现”，不要给假通过结果。
- 规范依据使用调研记录中锁定的官方版本并链接具体章节；遇到真实矛盾应提出待审决策，不能只写大段“后续确认”而没有 P1 可执行方案。

## 3 地址图、PMA 与参考模型配置

交付 `docs/architecture/memory-map.md` 和一个明确的机器可读平台配置（例如 `config/platform.json`）；选择一个事实来源，构建脚本据此生成或检查链接脚本、软件常量与参考模型参数。

- P1 RAM 基址 `0x80000000`、大小 128 KiB、复位向量同基址，明确末地址、栈、程序/数据/签名/页表保留范围，检查重叠、对齐和越界。记录配置版本，不能在多处维护互不验证的常量。
- 为 UART、计时器/中断、测试结果和可选浮点 MMIO 提出明确的不重叠地址与访问契约，区分 P1 实现、预留及最终功能。未实现区域不能被默认视为有效 MMIO。
- 明确 32 位整数/VA 与 34 位翻译 PA 的关系、高位 PA 的 PMA 拒绝、Cacheable/MMIO 属性、访存宽度和字节使能；首版同步/非对齐/副作用边界沿用设计书。
- 实际把软件冒烟的链接区域与 Spike RAM 区域统一为本轮配置，并在 Spike 上运行成功。不要保留 `-m128` 却把它说明成 128 KiB；参数由已安装 Spike 的实际支持方式确定。
- 区分 HTIF/tohost 宿主退出协议、Spike 引导 ROM 与未来 DUT 复位/FPGA 外设，说明参考启动阶段如何排除或对齐，不要求 DUT 仿造参考引导 ROM。
- 检查所选 Spike 版本接受目标 ISA/特权与 Svade 配置的实际方式，记录可用选项、命令/版本与缺口。接受参数不等于功能已全面验证，本轮不要求实现完整缺页软件；若关键配置不支持，报告问题和方案而非悄悄改变硬件目标。

## 4 共享类型与模块接口

交付 `rtl/include/core_config_pkg.sv`、`rtl/include/core_types_pkg.sv`（可有合理命名调整，报告说明）以及 `docs/interfaces.md`。

- 参数与位宽至少明确 XLEN/VA/PA、最终 2 槽、ROB 32 项、队列容量、ROB Token 项号/代次和对应类型；P1 可限制活动宽度为 1，不能把公共接口写死为只有一槽。
- 为 Fetch/Decode、Rename/Dispatch、Issue/FU、Writeback、Commit/Trap、存储请求响应、重定向/Flush 和最终 FPU 独立接口给出 packed struct/枚举或等效精确定义；体现逐槽 PC/异常、源值/Tag、结果、byte mask、请求 ID 与代次。
- 明确通用 valid/ready 的边沿采样、背压稳定、两槽连续前缀/接受数量、资源预留、同拍事件优先级、取消与在途响应所有权。不是所有接口都必须用同一种握手，差异必须解释。
- 用时序表覆盖：接收 0/1/2 槽、只剩一个资源项、槽间 RAW/WAW、入队遇到同拍广播、Flush 遇到完成/外部响应、第二提交槽异常，以及不可取消 Store/MMIO 事务遇到中断。
- 明确 Token 复用/代次回绕与排空规则，不能只用 ROB 项号识别旧响应。区分硬件必要字段和仅仿真使用的全局序号，避免将调试需求无说明塞进硬件关键路径。
- 增加最小类型/位宽自检夹具，实际导入并编译这些包，检查关键字段布局与非法参数；不写处理器功能模块来证明接口存在。

本轮接口是供管理方审查的候选冻结版本；常规字段选择可以自主提出，改变主架构或阶段范围须列为待审决策，不能擅自宣布已经批准。

## 5 退休/Trap 契约与测试计划

交付 `docs/architecture/retire-contract.md` 与 `docs/verification-plan.md`。

- 精确定义正常退休与 Trap 事件字段、两槽顺序、rd=x0、无寄存器写入、访存数据/地址/掩码、CSR、特权前后状态和实际下一 PC；缺失字段用明确有效性表示，不用零值冒充观测结果。
- 将当前 Spike 提交日志/观察接口逐字段映射到目标契约：已直接提供、可从已知指令推导、需要额外接口、尚不可用；明确 P1 能比较什么，后续 CSR/异常/中断/Sv32 需要补什么。
- 提供少量契约示例并做自动格式/字段检查；若使用合成记录，清楚标为格式夹具。真实 Spike 示例保留原始片段和转换依据，不称为 DUT 退休或 DiffTest 已运行。
- 将课程 C01—C17 与 P1/P2/P3 等阶段定向测试对应起来，尤其列出 P1 每类指令、Trap、停顿/握手、启动与终止的明确输入和预期结果。测试计划与已执行测试分栏，不能把计划数当作通过数。
- 列出 P1 模块任务拆分、集成顺序和验收标准，作为下一轮任务建议；本轮不自行启动 P1。
